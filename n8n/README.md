# تشغيل المشروع وتكامله مع n8n

> لا يرفع هذا المشروع كملف ZIP. انقل المصدر من مستودع GitHub خاص، ثم استورد ملف سير العمل JSON إلى n8n.

| المسار | الغرض | متى يستخدم |
|---|---|---|
| `n8n/water-ledger-workflow.json` | سير عمل لاستدعاء أحدث قياسات المياه المعتمدة عبر HTTP | عندما تكون المنصة منشورة وتريد قراءة البيانات في n8n |
| مستودع GitHub | نسخة مفكوكة من جميع ملفات المصدر والتبعيات | عندما تريد استنساخ المشروع أو تشغيله على خادمك |
| `n8n/environment.template.txt` | أسماء المتغيرات اللازمة فقط، بلا أي قيم سرية | قبل تشغيل نسخة محلية أو خادم مستقل |

## استنساخ المشروع

انسخ المستودع من GitHub إلى الخادم الذي يعمل عليه التطبيق أو على خادم منفصل:

```bash
git clone <PRIVATE_GITHUB_REPOSITORY_URL> oman-agri-vision-2040-v2
cd oman-agri-vision-2040-v2
pnpm install --frozen-lockfile
cp n8n/environment.template.txt .env
```

ضع القيم الحقيقية في `.env` محلياً فقط. لا ترفع `.env` ولا مفاتيح OAuth أو قاعدة البيانات إلى GitHub أو إلى ملف سير عمل n8n.

بعد ضبط البيئة شغّل الاختبارات والبناء ثم الخادم:

```bash
pnpm test
pnpm build
pnpm start
```

## استيراد سير عمل المياه

استورد `n8n/water-ledger-workflow.json` من شاشة الاستيراد في n8n. بعد ذلك استبدل `YOUR-PUBLISHED-DOMAIN` بعنوان المنصة المنشورة، ثم شغّل المسار يدوياً للتحقق. يدعم n8n استيراد سير العمل من ملف JSON أو من عنوان URL، كما يدعم عقدة Git لاستنساخ مستودع وتشغيل عمليات السحب والدفع في بيئة مستضافة ذاتياً. [1] [2]

سير العمل المرفق يقرأ فقط `agri.getWaterLedger` الذي يعرض القياسات المعتمدة. لا يملك صلاحية إدخال مسودة أو اعتماد قراءة جديدة، لأن تلك الإجراءات مقيدة بدور المشرف داخل المنصة.

## حدود التشغيل المهمة

n8n مناسب للأتمتة وربط الخدمات، لكنه ليس بديلاً عن استضافة تطبيق React وExpress. في n8n Cloud لا تتوفر عقدة تنفيذ أوامر النظام، بينما تعمل في النسخة المستضافة ذاتياً داخل البيئة التي يشغّلها n8n. لذلك استخدم رابط المنصة المنشورة مع عقدة HTTP لقراءة البيانات، أو شغّل التطبيق على خادم Node مستقل ثم دع n8n ينسق الإشعارات والتحديثات حوله. [3]
